# Added local adapter requirements

- Only six reviewed exact official documentation IDs map to request URLs. Contributions, arbitrary URLs/headers/credentials/query strings, private IPs, mapped/NAT64/tunnel/special ranges and mixed/empty/oversized DNS answer sets fail before connection. No automatic redirect or proxy route may change the target.
- Default Node HTTPS uses the checked public address through a custom lookup, original hostname/SNI/certificate verification, disabled proxy/pooling/session reuse and bounded response headers. Test dependencies may replace resolver/fetch, but cannot alter adapter allowlist or limits.
- Reserve at most four checks before asynchronous work; one request, two-second total deadline and 32-KiB body per check. Resolve/fetch/stream aborts and late completion never produce follow-on requests or successful state after timeout. Reject all redirects and unexpected final URLs, unsupported media/charset/encoding, invalid validators, malformed UTF-8/JSON, oversize/empty/truncated bodies and HTTP failures.
- Send ETag preferentially, otherwise Last-Modified. 304 requires a validated prior baseline and sent validator. Validated successful responses return SHA-256/validator metadata only; failure preserves prior hash/validators/checked timestamp. No response body is persisted, logged or published.
- Existing fixture runner, batch receipts, schema, Worker config, remote gates and scheduler remain unchanged. The local Node adapter cannot be passed into the fixture transport interface. No real article publishing or source-verification claim follows from a hash observation.
