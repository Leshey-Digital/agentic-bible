# Hosted scheduled maintenance composition

Connect a trusted scheduled selection to the existing acquired-source receipt checks, proposal/currency ledger, complete-candidate quality gate and publication lifecycle. Preserve automatic eligible publication and post-publication flags; hosted correction notes retain their separate human approval path.

The constructor is inert and default closed. It accepts server-pinned compiled targets, source profiles and schedule, explicit source/AI/quality/publisher ports and existing D1. It accepts no request-supplied candidate, source URL, credential or quality authority. Controlled extractive execution retains its identity. Native complete-candidate prose uses the existing Workers AI adapter, raw prompt bound and shared currency ledger; it does not relabel output as a fixture.

Generic/manual/legacy publication rejects versioned native provenance. A separate structural parser grants no authority. Native eligible publication requires an opaque process-local capability issued only after read-only verification of charged acquired sources, retained complete generation and exact durable quality admission. Restart requires a new capability, and the publisher rechecks authority before effects.

Use existing pipeline/proposal/quality ledgers, finite capacities and publisher history. Denial retains charges; unknown source, generation or quality outcomes cannot redispatch. No new service, credential, policy renewal, cron configuration, paid request, remote Git mutation or deployment is enabled here.

The first checkpoint implements the portable source/proposal/quality/publication composition and existing isolated publisher. Canonical schema/history and constrained expected-head integration are the next bounded source changes. Live operation and independent acceptance remain separate.

The canonical successor now reuses the shared `WriterOutbox`, bounded request session and extracted portable Git codecs. Version 3 native descriptors bind charged source/generation/quality evidence, exact canonical base commit/Markdown/predecessor, immutable history and the review pointer. GraphQL carries the fixed repository/ref and expected head; reconciliation verifies the complete tree and never redispatches an uncertain mutation. The same native action runs inside workerd without filesystem imports. A compiled server constructor may configure the native source, AI, trusted quality and canonical HTTP ports after a future operational grant; this checkpoint configures none.

Native provenance rendering distinguishes source-backed AI content, supplied fixtures and mixed snapshots. Fixture-only rendered bytes match the earlier checkpoint. Existing schema 1/2 Git records, fixture admission and archived source are not rewritten. Version 3 history uses the existing explicit source-pinned build mode and post-publication signed review catalog; public release remains a separate qualified deployment step.

A readonly schema check runs before job admission or source/model work; no migration is automatically applied.

Legacy small-source requests, verifier identities and receipts remain unchanged when these extensions are absent. Native canonical preflight verifies the exact expected head, complete baseline Markdown and artifact-derived qualified non-content code hash before source/model costs. Model article links must resolve to the compiled twenty-entry inventory.

One configured native action addresses one pinned baseline. After a canonical change, a new scheduled event using unchanged base configuration stops before new source/AI/quality costs; refreshing the trusted qualified baseline is a separate operational step. The code hash must come from the independently qualified implementation artifact, never be copied from an arbitrary current remote tree or supplied by a request. Current remote main is not automatically upgraded or merged. Completed receipt replay rechecks retained source/generation/quality authority and does not repeat remote calls.
