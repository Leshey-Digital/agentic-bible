# Proposed validation requirements

Actual cold-cache local SEO CLI startup under denied external networking must still serve the controlled static artifact. A positive control proves metadata requests are observed; the shared preview environment suppresses all metadata attempts. Local metadata/package-update caches cannot silently bypass the control, and diagnostic output contains only bounded categories/counts.

Every one of the same 24 reading pages must complete its own viewport and axe WCAG 2 A/AA and 2.1 AA checks on both desktop and mobile, with independently named results and unchanged per-page assertions/timeouts. The suite remains fixed in size with zero retries. Record selected browser versions and preserve the distinction between local Chromium 154 and the package-pinned CI Chromium 156.

This changes test orchestration and environment isolation, not public article/CSS/runtime output, correction authority/recovery, budgets or production authentication. Preserve both source heads and the correction composition checkpoint.

CI must select the bundled test-controller executable explicitly and verify the actual launched version equals its package manifest before running browser suites. Runtime logging alone is evidence of selection, not a mechanism that pins it. Preserve actual 154/155 observations separately from the pinned 156 validation.
