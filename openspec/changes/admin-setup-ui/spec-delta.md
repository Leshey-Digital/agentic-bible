# Added requirements

- The existing integration page offers only the fixed GitHub content and Typesafe Jev targets and uses each exact server route.
- Secret inputs remain password/write-only, clear on every attempt and integration change, and stay disabled until status is available. Submitted bytes never enter status, DOM projections or audit.
- Explicit status reload clears credential confirmation; the administrator must reconfirm the displayed revision before saving, including when a reload changes that revision.
- Connection status identifies controlled, provider or unverified evidence. A controlled successful check never claims real connectivity. Jev checks remain disabled without a documented non-billable contract.
- Setup includes truthful server build-manifest status, source identity when verified, and explicit distinction from live release or article publication.
- Existing contribution review, retry and correction proposal behavior remains usable and linked to setup.

# Acceptance scenarios

- A signed admin stores GitHub and Jev synthetic values independently against real controlled workerd/D1. Reopening each target returns only a constant mask and its own revision.
- A controlled GitHub success displays controlled evidence. Jev storage and status reads make zero additional outbound requests and no check is offered.
- Unknown or unavailable connection/build evidence never displays provider or live deployment readiness.
- Desktop and mobile support labels, focus, no horizontal overflow, and automated accessibility checks.
