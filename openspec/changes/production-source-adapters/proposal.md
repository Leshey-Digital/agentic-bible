# Bounded source acquisition and extraction adapter

The owner requests a concrete source path beyond the existing plain-text Tool use fixtures. The existing `collectMaintenanceSource` remains explicitly Node/fixture-only and rejects HTML; do not relabel it or convert extracted text into its original-body evidence. This separate component starts from production preparation `129a292067b9112522e7f24f733862d249290513` and owns only new maintenance-adapter modules/tests and these records.

Provide an opt-in callable Workers acquisition function over the existing exact official HTTP registry and D1 reservation/completion ledger. Retain original raw bytes/hash, bounded extracted evidence/hash, and reproducible original UTF-8 byte spans. Validate compiled source/profile identity and recompute extraction at the new verification boundary. No candidate can nominate profile authority or original independence. Publisher grouping is conservative metadata; every profile’s original lineage remains unknown, so this output alone is ineligible for publication.

Two strict HTML profiles cover the fixed MCP tools and OpenAI function-calling URLs. Expected canonical URL, title and one main element must all match. A deliberately narrow parser rejects unsupported entities, malformed structure, changed markers and over-limit evidence. Other registry sources and JSON bodies have no extraction profile and fail closed; no JSON endpoint is invented. Controlled fixtures establish callable behavior, not compatibility with current live HTML. An attempted ordinary raw read was denied by the environment proxy before origin; preserve that blocker and do not retry another transport.

Reuse existing request and storage bounds rather than creating a new ledger or framework. Raw bodies stay in the caller’s memory; no durable raw retention, crash recovery, scheduler, provider call, candidate writer or publication integration is claimed. A completed/ambiguous key is never automatically refetched. A separately reviewed raw retention/verified-source port and trusted lineage/semantic verifier are needed before generic provider integration. TypesafeJev’s API and capability remain unspecified; no text-generation assumption is made.

Alternatives are to keep fixture-only collection or broaden HTML/network limits. The former does not supply the requested adapter; the latter lacks measured compatibility and cost/security justification. This component adds no dependencies, migrations, routes, configurations, credentials, paid calls or deployment.
