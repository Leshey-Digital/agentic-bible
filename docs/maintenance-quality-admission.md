# Quality-gated maintenance preparation

`runMaintenancePipeline` accepts the distinct `{schemaVersion:2,kind:'quality-gated-maintenance-pipeline',...}` selection only with trusted `quality` wiring. The existing version 1 `controlled-maintenance-pipeline` remains a local synthetic demonstration and exact historical replay path. Both source/provider/Git/review ports still require controlled fixture identities; this checkpoint does not make the runner a production executor.

The quality control requires `profile:'quality-gated-v1'`, an explicit `minimumIndependentOrigins` between one and eight, and a trusted `trusted-semantic-quality-adapter-v1` port with stable identity/revision and an explicit controlled-test/production environment. No adapter is configured by default. A string claiming production does not authenticate an implementation: only reviewed server wiring can supply this port. Never expose its selection, implementation or lineage to request JSON, source content or a provider response. No model self-attestation is accepted as authority.

The verifier receives an exact candidate, paragraph manifest and source bytes under a combined hash. It must judge the entire candidate, including title, description and headings, find any claims omitted by the mechanical manifest, and return full claim coverage plus a supported/unsupported/unknown verdict for each paragraph unit. Exact quotations and hashes prove integrity only. They never prove truth, source authenticity, completeness or licensing. The bounded trusted adapter must independently perform those semantic and provenance assessments; controlled test reports do not establish production factual accuracy.

Every quality check must pass: completeness, substance, authentic citations, safety, nonspam and a distinct canonical update. Every unit must be supported. Unknown provenance/support/check outcomes deny publication. A mechanical short-text floor is only an additional safeguard, never a semantic quality classifier. No target volume, budget exhaustion or fallback permits filler publication.

Original-evidence identities are supplied by the trusted evidence assessment of each exact source body, not by the candidate, domain count or citation count. Syndicated/derived documents carry their original roots; any overlap connects them into one lineage, transitively. Unknown lineage denies. A one-origin policy is possible for a claim supported by an authoritative primary record; additional corroboration is an explicit policy choice, not a universal two-source quota. The adapter must not invent distinct original roots for syndicated copies.

Migration 0020 adds at most 64 quality admissions. Each event binds candidate/source/manifest hashes, identity/revision/environment and policy. A durable evaluating row precedes verifier invocation. Same-event races cannot dispatch twice. A crash after reservation or an unconfirmed/malformed/timed-out adapter response remains held; automatic replay cannot invoke again. Valid denials are durable terminal decisions. Decisions and reports contain bounded verdict/lineage data; raw source text is not copied into this audit. Terminal rows cannot be updated/deleted. Storage exhaustion stops admission; it never evicts protected records or creates filler.

The producer saves and accounts for its proposal first, then calls quality admission before publisher execution. Denial leaves the proposal and source charges intact, with no private or canonical publication. Migration 0021 records an append-only terminal disposition only after independently revalidating the exact known semantic denial against its saved charged proposal. The original pipeline journal/proposal/audit remain intact. A different event can proceed; the denied event always replays its denial without redispatch. Unknown provider/quality/write outcomes retain the original blocking behavior. Allow automatically continues the existing publisher, writer, complete-site build and flagged review ingestion. It creates no human disposition or live release.

The canonical writer independently requires the completed quality admission and emits a schema version 2 descriptor with the candidate-bound receipt. The new history reader accepts both formats and checks the receipt against the article revision. Older readers reject version 2 descriptors; direct downgrade is unsupported after their creation. Never rewrite history to make old readers accept a new record.

Run `node --test tests/maintenance-quality/*.test.mjs` using pinned Node 24.19/npm 11.9. Tests use actual local workerd/D1, controlled semantic decisions, controlled source/provider transports and owned Git repositories. No source is fetched outside tests; no model is called, no credential is installed, no real article is edited, and nothing is deployed. The twenty existing articles were deep-read previously, with sampled claims checked; this work does not assert that every claim was fact checked.

New restoration records append to that article's lineage and preserve every other head.
