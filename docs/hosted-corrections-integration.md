# Hosted correction connection

This successor composes frozen PR30 `18f76512ff53267ae2e0be113f2b1e67f8b7b02c` and PR31 `b11766919a3b99c4b29f8f7a208b9e6cc8313c69`. The [original gap report](hosted-runtime-gap.md) and [proposal protocol](github-content-proposals.md) remain historical evidence; their missing implementation ports are supplied here. GitHub → validated build → Workers Static Assets remains the canonical model. This does not merge source, update canonical reading, configure services or deploy.

## Shipped path

`src/hosted/worker.ts` now derives trusted ports from server bindings. `/admin/corrections/` verifies a signed admin assertion before returning its HTML/CSS/JavaScript. The admin explicitly loads the Git-pinned article source, writes a cited admin-authored note, confirms review, then separately requests a GitHub draft from the saved approval. Reloading lists saved approvals; uncertain requests retry the same key. Revocation cannot silently close an already created GitHub draft. Public intake, local fixture sessions and autonomous generation remain disabled. Specific note approval does not change the founder's autonomous article/post-publication-review policy.

`HOSTED_ADMIN_TRUST` is a server-configured JSON object with exactly `issuer`, `audience`, `assertionHeader`, `subjects`, `keys`. The only implemented assertion header is `cf-access-jwt-assertion`; it supports an Access-style signed gateway integration, not arbitrary browser-supplied role headers. No gateway, identity provider, membership or account policy is selected/provisioned. Trust must contain an exact HTTPS issuer, exact application audience, one to eight explicitly allowed opaque subject IDs and one or two public RSA JWKs (unique kid, RS256, sig, AQAB, 2048–4096-bit modulus). Private JWK fields and remote key URLs are rejected. Deploy-time key pinning requires deliberate rotation; there is no automatic JWKS network lookup. The signature is checked using native Web Crypto. Issuer/audience/subject, kid/algorithm, issue/not-before/expiry claims and a maximum one-hour assertion lifetime are checked. Writes require exact staging origin, non-cross-site metadata and `X-Agentic-Bible-Request: admin`; credentialed CORS is not enabled. Source preview also requires that custom header.

These checks follow the signature/issuer/audience model in [Cloudflare's JWT validation guidance](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/); accepting this implementation does not approve Cloudflare Access provisioning, identity membership or an IdP contract. The chosen gateway must protect both admin and admin-API paths and supply compatible assertions to HTML, CSS, JS and API requests. Token lifetime/key rotation/access removal need operational verification. Assertions and raw subject IDs are never returned to browsers or stored in approval records; reviewer references are domain-separated opaque issuer/audience/subject hashes.

`EDITORIAL_DB` must be an authorized D1 binding with shared migrations through `0009_hosted_reviewed_notes.sql`. The config in this repository contains no D1 UUID. Four retained approval payloads are admitted atomically; a collision never updates an existing row. Identical input returns the winning server timestamp. Application code never updates payloads; hashes are checked when loading authority. A privileged database operator can still alter data; fingerprint checks detect corrupted payloads and this is not a tamper-proof ledger. Revocations are separate append-only rows, at most one per approval, and only the approving admin may list/propose/revoke their records. No deletion/eviction API exists. Retention after the four-row limit needs an explicit reviewed policy. The source-preview singleton reserves four requests before work, at most twelve per UTC day, including failed previews. No unbounded job or automatic retry is introduced.

`GITHUB_CONTENT_TOKEN` is a server-only secret binding consumed by native fetch. It is absent from checked-in config. The wrapper accepts only the fixed repository/API origin, required read/create endpoints, GET/POST, safe internal headers, omitted ambient credentials and manual redirects; it injects authorization only after those checks. No client cookie/assertion/token is forwarded. Credential granting/installation, actual permissions and rotation remain unconfigured. Require narrow repository contents and pull-request permissions plus the event model needed for CI. In particular, [GitHub documents workflow suppression for most events created with GITHUB_TOKEN](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow); a draft receipt cannot prove required CI ran. No credential type is silently selected. PR30's four-row outbox, 12 invocation/24 lifetime request ceilings, source/tree/parent pins, create-only branch and historical replay semantics remain unchanged.

Absent/invalid trust, missing D1 or missing/invalid token keeps all hosted write ports closed. Runtime status reports configuration only, not a tested migration, approved identity setup, current GitHub draft, release or deployment. Release commit remains null/unverified. Admin source preview is an explicit action, not a paid call on public page views. Request/software limits are not currency enforcement or a complete HTTP-abuse defense.

## Verification and remaining release gap

`npm run test:hosted` bundles the actual shipped entrypoint and runs workerd/D1 with generated test signing keys and controlled GitHub responses. It proves cryptographic verification, wrong-claim/signature/key/algorithm/expiry/CSRF rejection, owner isolation, immutable admission collisions, corruption rejection, append-only revocation, capacity/source budgets, lost response and actual restart/replay. A proposed note is projected into an isolated twenty-entry source tree and built/indexed. `test:hosted-admin:browser` uses a test-only Node proxy simulating an authenticated signed gateway; the Worker itself receives/verifies real generated signatures with production code, not a test verifyAdmin port. Desktop/mobile tests cover source review, approval, saved retry/reload, draft and revocation, axe and overflow. Controlled URLs/PR numbers are fixtures, not live GitHub effects. Existing `test:hosted:browser` separately exercises real local Wrangler Static Assets reading/search of the projected source. These proofs do not establish a live IdP, live GitHub authorization, GitHub CI triggering or remote hosting.

Before a genuinely hosted MVP: independently accept/integrate source (main still has three entries), approve/configure gateway trust and membership/key rotation, bind/migrate real D1 and a least-privilege GitHub credential, verify actual proposal CI/events, pin release-source history and approved commit, implement/authorize build/deploy/rollback and verify the deployed release. Contribution terms/licenses/privacy/retention, monitoring/generation and actual monetary controls remain separate gates. No dynamic D1 article overlay, new service, model framework, automatic merge/deploy or license is substituted. Code rollback returns to either frozen source head; retain/export local approval/outbox data deliberately.
