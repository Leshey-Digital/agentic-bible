# Hosted maintenance history and review

This local successor continues preparation `9d5b82ad2817fa710bfa101f267c4d2ca603ffd6` without changing frozen PR38 `c35dd1e2a170205c2e5766ebf0983bd8d6a3a412`. It implements static revision views and authenticated post-publication review for the controlled writer profile. No public release or live service is implied.

## Reading and authority

Ordinary Astro builds include `/history/` and `/review/` with an honest empty maintenance state. Existing sourced working drafts and GitHub history remain available. Explicit `AGENTIC_BIBLE_MAINTENANCE_HISTORY_MODE=controlled-static-preview` requires `AGENTIC_BIBLE_SOURCE_COMMIT` equal to the build checkout's HEAD. The existing release source verifier also checks each current article byte against that pin. Git lazy fetch/transports remain disabled in the history reader.

The bounded verifier derives at most sixteen records from actual atomic writer commits, validating original record creation, parent/message/file set, descriptor/evidence/pointer hashes, previous chain and current article hash. Astro renders newest-first history, bot attribution, original source dates/hashes, escaped full Markdown and a linear body comparison. The comparison omits front matter and labels additions/removals/context. Revision/history/review pages and the public receipt catalog are noindex and excluded from article Pagefind/discovery. No API or model is called to read a revision.

`maintenance-history.json` contains only verified writer receipts/current markers and a source commit, with no private audit notes or reservation/budget fields. Release candidate packaging compiles the inventory hash of this catalog into the Worker alongside the existing release manifest binding. Authenticated handlers read only these exact bound bytes; a valid-looking substituted catalog is rejected. This is build authority, not proof of current live GitHub head, factual truth, private ledger integrity or production approval. The supported writer profile still says local-synthetic-only/livePublished:false.

## Signed admin review

`/admin/maintenance/` (also the `/admin/` workspace entry) and `/api/admin/maintenance/review` reuse the shipped RSA assertion verifier and explicit trust. No GitHub token is needed for a review decision. D1 plus a compiled catalog binding and configured trusted subjects are required. Default configurations have no live identity or D1 bindings. POST additionally requires the exact staging origin, same-origin request marker, JSON content and bounded body. The Worker returns no-store/noindex/CSP headers.

Migration `0013_hosted_maintenance_reviews.sql` adds one append-only audit table. Each request pins its catalog hash, current writer commit, expected audit version, decision, optional earlier target and explicit confirmation. A single immutable `INSERT … SELECT` bounds total rows to 64, versions per receipt to 16, and admits one concurrent version winner. There is no follow-up write that a losing key can authorize. Exact input and owner are required for replay. Row fingerprints bind owner, input and timestamp; stored projection fields are checked before reads/replays. Reviewer subjects become opaque hashes, and notes remain behind authentication.

`reviewed` and `follow-up` add human dispositions without changing article text or original flags. A fresh action on an earlier receipt or changed catalog is rejected. Replaying the original exact request after restart or a newer build returns its historical result, marked noncurrent where applicable. A stale audit version requires reload and reconfirmation while retaining the note. Lost responses retain the same request ID for safe retry; a failed audit reload never turns a confirmed save into an unknown write. An older response preserves a newer draft.

## Revert semantics and remaining gaps

`revert-requested` requires an earlier retained writer commit, current receipt/catalog and audit version. The audit stores the exact restore target and reason, while `articleChanged:false`, `flagsRemoved:false` and `canonicalRevertSupported:false` remain explicit. The UI says the request is saved and the article unchanged. The current writer has no guarded canonical revert contract. A future implementation must append a new canonical revision, retain old records, revalidate current head/authority and define source/flag behavior; resetting Git or overlaying article text in D1 is not an acceptable substitute.

No notification delivery, production writer record profile, live GitHub freshness check, production identity setup, actual credentials, remote migration, paid provider/source call, indexing, deployment or license decision is included. Public review flags remain a static publication record rather than a live private disposition feed. Review does not become prepublication approval.

## Validation and rollback

Commands and exact results are recorded in the final local handoff under the actual Git worktree metadata directory. Native tests execute the shipped Worker in local workerd/D1 with ephemeral test signing keys and real owned-Git writer receipts. The history build is a real isolated Astro/Pagefind checkout. Browser tests use a loopback-only gateway that supplies controlled signed assertions and simulates response loss only after durable D1 completion. Its control endpoints and keys are test code, never part of deployment configuration.

Rollback leaves this local branch unpublished or returns to `9d5b82ad`; no remote database or resource was changed. PR38 and every source checkpoint remain unchanged. This successor needs its own independent review before acceptance.
