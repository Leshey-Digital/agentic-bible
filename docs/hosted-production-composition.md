# Hosted route composition

`src/hosted/worker.ts` remains closed when optional bindings are absent or invalid. `configuredPorts()` mounts contribution routes only when the existing signed admin trust, D1, an exact moderation-policy object with valid terms/privacy paths, and a base64-encoded 32-byte intake HMAC key are present. It mounts integration settings only when signed trust, D1, a valid key ID, and a base64-encoded 32-byte AES-256-GCM key are present. Both imported keys are non-exportable. Missing or malformed optional values do not enable a route. See the [documentation-only example](runtime-bindings.example.jsonc); it is not referenced by an active Wrangler configuration and contains placeholders only.

The intake limiter HMACs the Cloudflare `cf-connecting-ip` value with a domain-separated key before passing the digest to the existing D1 rate limiter. The raw header is not persisted. The new `hosted_abuse_counters` table contains only a UTC day number, one of eight fixed outcomes, and a saturating count. It has no request, IP, user-agent, email, identity, source URL, or submitted-content columns. Counts saturate at 1,000,000 per outcome/day; the runtime prunes older rows on each counter write, and the authenticated `/api/admin/abuse-counters` projection returns only the last 14 days. If there is no later counter write/read, old rows can remain physically stored until the next counter access; no scheduled deletion is provisioned.

Counter storage failure cannot turn an otherwise successful submission response into success: the Worker responds with a generic 503. Submission writes are idempotent, so a client retry receives the existing replay-safe receipt. Rejected requests retain their rejection response even if a counter write fails. Abuse counts are operational visibility, not a request budget, account-wide spend cap, or billing control.

The integration-settings route continues to use the existing encrypted D1 vault. Jev connection evidence is set to `unverified`; configuring a Jev secret only proves that encrypted settings were saved. Jev's connection test remains unsupported and sends no provider request. No secret is returned to the browser, and no provider API is called by the composed-entrypoint tests.

`npm run test:production-hosted` bundles and runs the actual `src/hosted/worker.ts` default entrypoint in local workerd with disposable D1, generated local signing keys, and controlled outbound interception. The positive composition test covers public intake, signed administrator review, status projections, write-only Jev settings, restart persistence, counter retention, and zero provider dispatch. Synthetic test success is not live identity, provider connectivity, hosted activation, or deployment evidence.
