# Full wiki build isolation successor

This separate fix starts at immutable PR17 `6f6fbd69bdaab9107f0eb88955d8da8bd1f3450d`; PR17 CI [38968747632](https://github.com/Leshey-Digital/agentic-bible/actions/runs/38968747632) passed every step. Its independent review remains separate. The final handoff/draft PR records this successor's exact head and checks.

SEO inspection reproduced `EXDEV` while Astro moved an asset from the caller checkout's `.astro/.prerender` into an isolated `/tmp` output. The pinned Astro 7.4 implementation `getOutDirWithinCwd` falls back to cwd's `.astro` when the supplied output directory is outside cwd; static prerendering uses that path, independently of cacheDir. PR17's bridge passed the caller repository as cwd and staged output in the actual Git directory, outside that cwd. Concurrent builds could therefore share/remove intermediate files. This is a confirmed isolation defect and a plausible mechanism for the earlier concurrent failure; the historical failure's exact cause remains unproven.

The new [regression](../../tests/wiki-bridge/build-isolation.test.mjs) failed against PR17 with `caller-owned prerender cache was deleted`. It starts two independent full wiki builds from successful charged actual local D1 receipts, waits for both outcomes, and checks a caller cache sentinel/inventory, ordinary dist when present, original Markdown, charges and complete activations. The fix sets child cwd to its captured temporary project and builds to that project's own dist. The parent inventories/bounds every completed file before copying into its owned bridge staging directory across filesystems. Pinning, full-site sealing, expected-parent activation, rollback and receipt logic stay unchanged.

Reproduce with `npm run validate`, `npm run test:wiki-bridge:browser` and `npm run staging:check`. The initial targeted red log, green log and final validation/browser/dry-run logs are retained privately as `build-isolation-*.log` in this worktree's actual Git directory. No dependencies were installed. Original Markdown, ordinary caller cache/dist, interactive state and all earlier remote heads are preserved. No model/provider call, credential, account, remote resource, main merge, deployment, live schedule, tracking, ad or license selection occurs.

Local checks passed: targeted red-to-green regression; full validate with 96 tests (including 11 bridge checks), 79 checked files and zero diagnostics; final documentation check 99 Markdown files/91 relative links; canonical bridge browser journey; 16 desktop/mobile reading browser checks; 54-asset staging dry run. Exact-head CI and independent review are reported in the draft PR/handoff rather than inferred from local success.

Process death can still leave bounded private temporary/staging directories for investigation; existing attempt/admission limits remain. This local fix adds no production identity, trusted distribution or cross-host release semantics. Code rollback is returning to PR17 and leaving successor stores unused; PR17 retains the known isolation defect. Independent exact-head acceptance of this fix is required before composition/release.
