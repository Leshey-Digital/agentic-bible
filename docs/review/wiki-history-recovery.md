## Reproductions and behavior

Local native D1/full-build reproduction found three literal `/local-publications/` occurrences in canonical current text and zero in its canonical retained history. The publisher's own original history retains them; the bridge's global replacement corrupted the copied text. The [full history regression](../../tests/wiki-bridge/history-recovery.test.mjs) retains literal paths in current, original publisher history and canonical history, then repeats history checks after a successor and rollback. A separate [HTML fixture](../../tests/wiki-bridge/html.test.mjs) verifies real code text `fetch("/local-publications/")`, attribute-looking text, comments, raw script/style/textarea bodies, unrelated attributes, external URLs and fragments. It does not invent an Article code-block type.

The rewriter tokenizes HTML tags and attributes, rebases intended publisher href/src values and pins intended root href/src/action values. It never globally substitutes a URL prefix in text. Tests cover actual current/history pages and actual link attributes; prose that looks like an attribute remains prose. The known fixture vocabulary uses well-formed generated publisher/Astro HTML; this is not a general untrusted-HTML sanitizer. Supplied article text is still escaped/technically validated by the existing publisher.

The real SIGKILL build-started reproduction left a new `agentic-wiki-bridge-*` capture outside store accounting on the predecessor. No old or sibling directory was swept. New captures live under `<owned bridge root>/captures/capture-<job hash>-<attempt>-<random>/` with `capture.json` binding schema/event/job/attempt/site. Every retained slot reserves **64 MiB**, regardless of its smaller current byte size, in `status.storage` and admission. Status reports slot count, reserved bytes, total accounted bytes and 192 MiB limit. Build-plan JSON is bounded to 8 MiB; live capture size is monitored with a 64 MiB software stop and bounded child deadline. Dependency symlinks refer to the existing installation and are not newly copied storage. Completed output remains separately bounded to 16 MiB and copied into owned staging.

Healthy cleanup removes only the exact random capture created by that invocation after a clean child exit (or before any child exists). Failed/killed children retain their capture, even when the parent is still alive. The expected parent is passed before spawning; the child refuses an adopted/mismatched parent, checks parent continuity every 100 ms and has its own 45-second deadline. A killed process can leave its capture for investigation; recovery retains and charges it instead of deleting it. It never identifies deletion targets by PID or site ID, and no global /tmp sweep exists. The 192 MiB admission check includes retained capture reservations, a new 64 MiB capture, 16 MiB staging and the existing rollback reserve. Two retained slots can therefore conservatively block new work before three build attempts are spent. This explicit stop requires operator investigation; it does not retry/rebase or purge diagnostics automatically. Software sampling/admission bounds are not filesystem quotas or monetary enforcement.

The SIGKILL test verifies no new global capture, explicit retained reservation after successful exact recovery/restart, unchanged D1 charges and capacity refusal without deleting another owned capture. The [concurrent isolation test](../../tests/wiki-bridge/build-isolation.test.mjs) now also requires identical site IDs in two distinct stores; both builds finish and caller cache/dist/Markdown/charges remain intact. Thus site identity is never used as a workspace deletion authority.

Unmarked global leftovers created by old PR17/PR18 runs cannot safely be adopted or deleted by this fix. Preserve them for deliberate operator investigation. Fresh fixed-head runs allocate no unaccounted global projects. Existing interactive state, original Markdown and all earlier heads are preserved.
