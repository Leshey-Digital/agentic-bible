## Minimal Cloudflare collection proposal

Read-only account inventory confirms no Web Analytics site for this hostname and no measurement binding on production. [Web Analytics](https://developers.cloudflare.com/web-analytics/about/) is free and useful for page/performance signals, but its [FAQ](https://developers.cloudflare.com/web-analytics/faq/) explicitly does not support custom events. It cannot alone measure search outcomes or contribution states. Do not send custom events to its beacon endpoint. Its six-month access window and automatic zone-wide injection are also a different privacy choice from a public-page allowlist.

Recommend one **first-party Workers Analytics Engine** path for all selected page/search/contribution/error counters, rather than installing Google/Clarity plus a second custom system. Proposed account: existing Agentic Bible account `c370be29e4065365de03bc8652da2cdc`. Proposed bindings/datasets: `PUBLIC_MEASUREMENT`→`agentic_bible_public_v1` on production, and a separately named `agentic_bible_staging_measurement_trial` dataset only for a labelled synthetic staging trial. No staging editorial DB or secrets go to production. Nothing is bound or created in this assignment.

The [supported binding](https://developers.cloudflare.com/analytics/analytics-engine/get-started/) writes via `writeDataPoint`; a dataset appears on its first write. No API key is needed for that write binding. Read/report through the owner's existing Cloudflare dashboard or an already authorized account read route; do not create a read token or put a connector credential into the Worker. A built-in admin dashboard would need its own supported read authority; it is not silently included.

Proposed ingress: same-origin `POST /api/measurement`, no CORS grant, strictly allowlisted projected fields only, bounded batch of at most 8 events/4 KiB, no credentialed cross-origin requests, no automatic retries or persistent event queue. Client max 32 events/page remains. Consent starts denied, revocation stops the next send, DNT/GPC stop collection, private/admin/API/staging pages are excluded from production collection. A separately approved compiled integration, public notice and consent/revocation UI must exist before the recorder is installed. Do not accept a request's claim of consent as proof that policy requirements have been met.

Persist only schema version, canonical public path/article, finite event/outcome/result bucket, expansion-attempt flag and count. Never copy query text, URL query/hash, IP, referrer, device/user identifier, proposal content, request/approval IDs, prompt or error text. Analytics Engine also adds an event timestamp and retains data for [three months](https://developers.cloudflare.com/analytics/analytics-engine/limits/); this is not a day-only or 30-day store. That retention must be explicitly accepted, or choose a separately reviewed aggregate D1 design instead. Cloudflare necessarily handles request network metadata in transit; no application anonymity guarantee is made.

[Pricing](https://developers.cloudflare.com/analytics/analytics-engine/pricing/) currently says Analytics Engine is not billed; published future Workers Paid allowances are 10 million writes/1 million reads monthly, then $0.25/$1 per additional million respectively. This is not a permanent free-service guarantee. Proposed initial operating target ≤100,000 datapoints/month and ≤1,000 report queries/month, under existing account configuration, no upgrade/subscription or budget increase. Verify current billing/allowance headroom immediately before activation. A target, per-page bound and billing alert are **not** an enforceable global spend cap. If billing starts or a strict additional monetary cap is required, keep collection off until a reviewed durable global admission counter exists; do not claim these hooks enforce it. Existing Worker request costs also remain applicable.

`writeDataPoint` is non-blocking; successful Worker return is not proof of durable ingestion. The real collector/transport still needs local implementation, admission/abuse limits, redacted error behavior and staging readback before production activation. Report accepted/dropped/uncertain and sampling status, never infer unique visitors or mark missing data zero. Sampling-aware reports must use provider weights where applicable.
