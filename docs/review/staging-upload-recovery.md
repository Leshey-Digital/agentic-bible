## Reproduced fault and recovery

`node --test tests/release/cli-recovery.test.mjs` builds an actual clean local Git/Astro/Pagefind candidate. A separate loopback HTTP provider receives requests from package-locked Wrangler **4.151.1**. Its first version-create POST commits the version, then either drops the response or returns 500. Wrangler retries and creates a second version with the same candidate/request marker. The harness verifies the actual posted Worker SHA-256 and bindings for both versions, then sends SIGKILL immediately after the actual `ports.upload` returns (including parsing the CLI output), before the controller can record the version ID. The retained journal is `upload-pending`, `versionId: null`, with zero activations.

The precise reviewer baseline was also rerun on frozen PR33 `e924db11b32171ee28006aabe488c3615a54f583`; its release provider/controller/tests are byte-identical to PR34. Both faults yield exactly two create POSTs, `upload-pending`, `uploadAttempts: 1`, `versionId: null`, zero activations and `release_duplicate_versions` on the identical candidate/permit/request/journal retry. The fixed retry validates both remote version details and chooses the lowest UUID, verifies the candidate's complete public assets/runtime status and records success, without creating a third version. The test checks both list orders, conflicting sibling details/bindings, source/current-version changes, durable selection, already-active selection after losing a workspace, receipt replay and served corruption. Adapter tests cover six matches, excess matches, history boundaries, duplicate/malformed IDs and missing selected versions. Existing real local Workers serving and rollback regressions remain intact.

The controlled provider reports its assets already cached; it does not emulate a real Cloudflare asset storage service. Every public asset is nevertheless checked against the candidate during controlled verification, and the retained release suite separately runs native Workers Static Assets. External CLI connections are blocked by a test-only dispatcher. A cold CLI may attempt a package-update GET; the harness permits only a blocked `registry.npmjs.org` read and records it. No Cloudflare or other external network connection is made by this CLI fault harness. Synthetic token strings are not credentials.

## Selection and trust boundaries

Every exact candidate/request marker is checked, including siblings that will not be selected. Reject changed detail markers, wrong IDs and unreviewed bindings before activation. The controller also validates siblings after a successful CLI upload and when a journal already contains a selected version. Prefer the validated successful CLI return, a durable journal selection or this operation's active selection; otherwise sort UUIDs lexicographically. A disappeared selection or disagreement between journal and own active version fails closed. No versions are deleted, no force parameter is introduced and no foreign request/candidate is adopted.

At most six exact-marker versions are admitted. This bounds detail reads within the existing 16 direct-adapter-call limit, including the fresh-upload path. It corresponds to two retained-journal upload invocations and Wrangler's three create attempts per invocation. Wrangler's preflight/asset/session calls are separate from the direct adapter counter. History reaching 100 items still fails closed; no unbounded enumeration or global attempt-accounting claim is added.

Remote annotations are provenance markers under the existing owner-enforced exclusive deployment-writer prerequisite. They do not cryptographically prove remote Worker/assets bytes or authenticate a competing writer. Local candidate inventories/hashes/source/target and full served bytes/runtime binding remain mandatory. Unselected siblings are never activated to inspect their bytes. Expected-version observations, fixed workflow concurrency and source rechecks remain; the provider has no global compare-and-swap, so an external writer can still race an in-flight activation. Owner setup must exclude competing Builds/manual writers. This fix does not claim to solve that prerequisite.
