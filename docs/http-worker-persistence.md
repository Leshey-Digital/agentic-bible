## Transport boundary

The Node adapter remains `createHttpSourcePass` in `http.ts`, using the original public-address validation and HTTPS pinning. Its response validation now lives in `http-core.ts`; the fixed six-source registry is runtime-neutral in `http-registry.ts`. `http-policy.ts` retains Node-only address classification. All original Node adapter tests remain applicable.

`createWorkersHttpPass` in `http-workers.ts` uses native Workers `fetch` with a new fixed GET request: exact allowlisted HTTPS URL, omitted credentials, no cache, manual redirects and allowlisted headers. It shares conditional validators, explicit HTTP provenance, SHA-256, strict MIME/UTF-8/JSON/encoding and length checks, 32-KiB accepted body, two-second total deadline, cancellation and last-good preservation. Response headers over 8 KiB are rejected after fetch returns headers; this is an application acceptance bound, not a configurable wire-level header cap. Transport/platform buffers can receive extra bytes before cancellation. No raw source text is returned or persisted.

**Native Workers fetch does not implement application DNS pinning or connected-peer inspection.** [Cloudflare's HTTP compatibility documentation](https://developers.cloudflare.com/workers/runtime-apis/nodejs/http/) lists unsupported `lookup`/connection options; the pinned local workerd probe rejects a custom `lookup` with `ERR_OPTION_NOT_IMPLEMENTED` before any outbound request. [DNS documentation](https://developers.cloudflare.com/workers/runtime-apis/nodejs/dns/) also lists unsupported lookup APIs. [HTTPS compatibility](https://developers.cloudflare.com/workers/runtime-apis/nodejs/https/) does not support the Node TLS option set. [Request options](https://developers.cloudflare.com/workers/runtime-apis/request/) constrain `resolveOverride` to zone-owned hosts, so it cannot pin these third-party documentation domains.

The Workers implementation trusts Cloudflare's DNS/TLS/platform routing for the fixed official names. It cannot demonstrate that DNS returned only public addresses or that a connected peer matched a checked address; compromised official-domain DNS and platform routing are outside this application guard. There is no misleading preflight DNS check followed by an independently resolved fetch. This is a different egress trust model from Node. Exact URL selection prevents contributed/private URL inputs; it does not recreate Node's IP guarantee. App entry points remain disconnected pending independent transport/security review and an explicit integration decision. No deployment readiness claim follows from local runtime compatibility.

## Durable single-source action

Trusted code may call `checkHttpSource(new HttpObservationStore(db), sourceId, requestKey)` using the existing editorial `SqlDatabase`/D1 repository interface. It returns a small serialized receipt with `status` and the adapter result. The caller supplies one fixed source ID and a UUID command key, never prior state or a URL. The service reads last-good metadata from D1, reserves before dispatch, performs at most one fetch per invocation and atomically records the outcome. No HTTP application endpoint exports this action. Optional fetch/clock dependencies are trusted test wiring, never remote request fields.

Migration `0005_http_observations.sql` is additive to the existing local D1 database:

| Table | Purpose and bound |
|---|---|
| `http_source_state` | Six registered source rows: `mode=http`, hash, ETag, Last-Modified, checked timestamp, revision and completion token. No text. |
| `http_request_budget` | Singleton monotonic UTC-day counter, at most 20 reserved attempts per day. |
| `http_check_jobs` | At most 128 command receipts/jobs; one source per immutable key, at most three attempts. Results limited to 2 KiB. |
| `http_request_reservations` | One token per charged attempt, at most 384 across the bounded job set; outcome and successful accepted-byte count, with no raw response. Failed/interrupted transfer size is unknown (`NULL`). |

No existing fixture/publication/settings table or row is repurposed. HTTP observations do not create source events, publication candidates or article revisions. Do not send these results into fixture tables or treat a hash change as verification of factual content. A future publisher must define an independently reviewed provenance/evidence contract.

## Atomic budgets, retries and interruption

D1 serialized `batch` transactions fence each claim, reserve an attempt and increment the daily counter together before fetch. The global active-lease limit is four, with one active lease per source. A competing request with the same key/source cannot dispatch while its lease is active. A persisted success or terminal failure replays without a fetch; a key bound to another source fails. Capacity/accounting/missing-schema failures stop before network dispatch. Failed/ambiguous attempts remain charged; no automatic refund occurs.

Retryable network/timeout/408/429/5xx results store `retry` with a one-second then two-second delay. A caller must explicitly invoke the same key after the persisted due time; there is no automatic retry loop or scheduler. Calls before due replay the previous retry result. Three total attempts end the command. A ten-second lease is longer than the two-second fetch deadline. Restart recovery of an expired lease marks its reservation abandoned and charges a fresh attempt, up to three. An interrupted third attempt becomes terminal. Token/expiry/source-version checks reject late completions; atomic completion updates source metadata, job receipt and reservation together. SQL failure rolls them back. Conservative charging covers crashes after reservation and before dispatch as well as unknown network outcomes.

Day counters advance only forward on trusted server time; a clock moving into an earlier day blocks claims rather than resetting counts. They measure reservation day, including requests crossing midnight. They do not retroactively certify actual wire traffic after an interrupted request; platform abort/termination guarantees still matter. There is no automatic receipt pruning or budget-history reset beyond advancing the singleton day. At 128 jobs, new keys fail closed until a separately reviewed retention/archive policy exists; supported retries and receipts are not evicted.

The limits bound source-request attempts and local metadata growth. **They are not monetary budget enforcement.** They do not cap inbound abuse, CPU time, D1 reads/writes, platform bandwidth, baseline Workers billing or model currency. No paid provider/model is connected. Numeric paid-job allocation/pricing/reservation/reconciliation and operational stop controls remain prerequisites to paid automation. Native library functions can be called by trusted code outside this repository service; future app integration must require the durable action rather than bypassing its reservations.

## Local verification and practical limits

Run `npm run validate`, which includes `npm run test:http-sources` and `npm run test:http-worker`. The Worker suite bundles a test-only entry with already-installed esbuild and runs the pinned Miniflare/workerd dependency. Every outbound request is intercepted by a controlled service. It applies the real migration stack to disposable `.git/http-observation-worker-state`, reopens that D1 state on runtime restart and checks headers, 304, redirect/size/encoding/header/deadline failures, atomic parallel admission, retry/backoff/exhaustion, stale leases and transaction rollback. Test-only claim/probe routes are never included in Wrangler application configuration. Existing interactive `.wrangler/editorial` is neither migrated nor reset by this suite.

Three bounded manual reads were attempted for the allowlisted Claude overview, OpenAI function-calling guide and MCP tools specification using identity encoding, no redirects, a two-second timeout and 32-KiB maximum each. All failed with curl exit 56, upstream status `000` and zero downloaded bytes in this environment; intermediary headers are not source metadata. No source response, actual adapter HTTPS/TLS handshake or practical page-size/validator compatibility was established. There was no retry through another route. The 32-KiB cap, identity requirement and two-second timeout remain unchanged. Real official HTML may exceed them. Do not infer readiness from synthetic small responses or widen bounds without measured compatibility and cost/security review.

See [verification evidence](review/http-worker-persistence.md). No push, PR, remote migration, schedule, merge or deployment is performed.
