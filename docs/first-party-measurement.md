# First-party aggregate measurement

Implemented locally, disabled by default. No dataset, database, live binding, policy or collection has been activated. This connects the existing minimized reader/search/contribution projections to real injectable Workers Analytics Engine `writeDataPoint`, without external SDKs or credentials. Server entry points are `configuredMeasurement`/`measurementRuntime`; the staging hosted router also exposes the exact `/api/measurement` route. Production's static module entry must compose `measurementRuntime` rather than inherit the private staging router or its noindex headers.

## Activation and privacy decision

Proposed owner decision: allow optional first-party page/search-outcome/contribution-outcome/error counts on agenticbible.si in existing account `c370be29e4065365de03bc8652da2cdc`, using Analytics Engine dataset `agentic_bible_public_v1` and a **separate** quota-only D1 binding `PUBLIC_MEASUREMENT_DB`. D1 is existing Cloudflare infrastructure, but this dedicated counter database is not currently provisioned or bound. Never reuse editorial D1 or secrets. No new subscription, credentials or paid-plan change is proposed. Verify account pricing/allowance headroom and exact target bindings before any activation.

Collection is opt-in, default denied, honors DNT/GPC, and can be revoked in the same or another tab. The only persisted browser value is a policy-versioned granted/denied preference, not an identifier. The visible controls explain that no query text, proposal contents or visitor IDs are collected. Cloudflare handles network metadata in transit, adds an event timestamp and retains the coarse events for three months; this is not a day-only anonymous store. Approval of that purpose/notice/retention is separate from implementation.

Only a separately approved canonical production build may set `AGENTIC_BIBLE_PUBLIC_MEASUREMENT` to `{"schemaVersion":1,"enabled":true,"policyRevision":"aggregate-v1"}`. Staging, synthetic and private pages cannot render the controls. Server metadata separately needs `PUBLIC_MEASUREMENT_POLICY` with those fields plus `origin:"https://agenticbible.si"`, `hourEvents:1000`, `monthEvents:100000`; missing/invalid/disabled metadata fails closed. No checked-in configuration enables these values.

## Enforcement and storage

Same-origin JSON POST only; maximum4096 streaming bytes/eight events, two-second read deadline, exact schema/version and finite public path/event fields. Unknown fields, query/hash paths, raw search text, request/user identifiers, proposal/error text and private routes reject the whole batch before quota/provider effects. Consent in an anonymous request is a declaration, not proof of human intent or unique readership. Counts can be spoofed within admission limits; never present them as unique people.

The client limits32 events per page across consent toggles, bounded queues, one in-flight request and a five-second send deadline. Every dispatch rechecks consent/storage/DNT/GPC. Revocation clears pending data; it cannot retract a request already dispatched. Failed/unknown sends are not retried or persisted. Two tabs share revocation; deleting/clearing the preference stops collection.

Apply `measurement-migrations/0001_aggregate_quota.sql` only to the separately approved measurement database. It is deliberately outside editorial migrations. One global row stores current UTC hour/month counts and a server-clock high-water; one atomic UPSERT enforces cross-isolate caps. Reserve all events before submission; retain allowance on lost counter responses, timeout, partial dispatch, transport failure or period change. No refunds, retries, visitor keys, per-event timeline or editorial records enter this database. A backwards clock or policy mismatch closes admission. Current-period global counts are overwritten at period progression; this is not a visitor-history store.

Maximum1000 admitted events/hour and100000/month also conservatively cap data points, since equal rows aggregate within each batch. These are application event limits, **not a cap on total Workers/D1 request billing**. Verify current costs and request-abuse posture before activation. Rate caps/alerts alone never guarantee total account spend.

Analytics Engine label order is fixed: schema, server UTC day, canonical page, event, result/outcome/component, selected article, keyword-expansion flag. `double1` is count; the sole sampling index is canonical page. No URL queries, cookies, referrers, IP, device IDs, secrets, raw errors or submissions are passed to the transport. Reporting must account for Analytics Engine sampling. Native submission is nonblocking:202 means `submitted_unconfirmed`, never durable ingestion. A separate authorized dataset readback is required for live acceptance. Official contract: https://developers.cloudflare.com/analytics/analytics-engine/get-started/ .

Disposable tests cover denial, revocation across tabs, malformed/raw input, oversized/slow streams, actual D1 atomic concurrency/caps, stale clocks, delayed/unknown effects, consent-toggle limits, failed sends and default-off build/runtime. Mock binding calls are not live ingestion or privacy approval.
