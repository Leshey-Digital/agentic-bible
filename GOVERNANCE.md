# Governance

The founder owns product direction, licensing, budgets, monetization, and external-account decisions. Authorized maintainers review code changes. On 2026-10-16 the founder approved automatic article publication, with articles that need review flagged for human admin review after publication. Human prepublication editorial approval for every article is not required. Earlier proposed initial manual publication review is superseded. Code review and release authorization remain separate from editorial publication policy.

Automatic publication must enforce technical validity, malicious-content rejection, source/provenance requirements, reversible revisions, budget stops and audit records. Missing evidence or unsafe executable content is a validation failure, not a reason to quietly substitute a universal human preapproval policy. Flag uncertainty and consequential issues for the in-app editorial queue. The owner designated editorial@agenticbible.si as the editorial destination; no mailbox, email delivery or admin identity is configured by this slice.

The founder approved open-source direction and a $10 monthly operating target, MVP scope and reviewed merge/staging/production release authority. Specific code/content licenses and numeric Jev allocation remain undecided. This application slice does not deploy or merge; independent review is still pending.

## Editorial standards
- Prefer original documentation, research, standards, and reproducible examples. Distinguish facts, vendor claims, analysis, uncertainty, and dated behavior.
- Cite claim-level evidence; record publication/version and last verification dates. Link to sources rather than reproducing substantial copyrighted text.
- Avoid promotional ranking, invented citations, unsupported superlatives, or manufactured freshness.
- Document conflicts of interest and sponsorship. Ads must not influence editorial conclusions.
- Correct substantive mistakes with a visible revision note; preserve Git history and record review identity.
- Automatically publish valid articles and flag those needing human admin review afterward. Preserve evidence, correction history, audit identity and an emergency off switch. Policy implementation is pending; no GitHub protection rule or publishing pipeline is implied.

Open-source intent does not select legal terms. Before public contributions: select separate code/content license treatment as appropriate, publish submission terms and attribution rules, choose moderation and private security contacts, and establish retention/deletion policy.
